# Vite·Next.js 동등성 비교

기존 Vite 앱은 마이그레이션의 동작·화면 기준선으로 사용합니다. 두 프론트엔드는
같은 5173 포트를 사용하므로 동시에 실행하지 않고, 비교할 앱을 하나씩 번갈아
실행합니다.

```bash
# Backend: http://localhost:8080
./gradlew bootRun

# Vite와 비교할 때 실행 중인 Next.js를 먼저 종료합니다.
# Vite: http://localhost:5173
cd frontend
npm run dev

# Next.js와 비교할 때 실행 중인 Vite를 먼저 종료합니다.
# Next.js: http://localhost:5173
cd frontend-next
npm run dev
```

## 비교 원칙

- 경기 목록처럼 서버 상태를 바꾸지 않는 화면은 같은 viewport에서 앱을 번갈아
  실행하며 비교합니다.
- 대기열 진입, 좌석 선점, 예약, 주문, 결제는 두 앱에서 동시에 실행하지 않습니다.
- 상태 변경 흐름은 서로 겹치지 않는 테스트 사용자와 좌석 데이터가 준비된 경우에만
  앱별로 순차 실행합니다.
- 준비된 데이터가 없으면 자동 초기화를 가정하지 않고 mock 검증과 실제 연동 수동
  체크리스트를 분리합니다.
- 취소 가능한 예약과 주문은 기존 취소 API로 정리하고, 결제는 PG sandbox 또는
  MOCK provider에서만 비교합니다.

Turbopack 프로덕션 빌드는 현재 Codex 실행 환경에서 CSS 처리용 보조 프로세스가
로컬 포트를 열지 못해 중단되었습니다. 같은 소스를 Webpack으로 빌드했을 때는 모든
정적·동적 route 생성까지 완료되었으므로, 로컬 터미널이나 CI에서 Turbopack 빌드를
한 번 더 실행해 환경 제약 여부를 최종 확인합니다.
